## What this PR delivers
- New **opt-in** authenticated endpoint mode \`GET /api/cron/historical-ingestion?mode=FORWARD&providers=fred&fredReleaseAware=1\`. Existing combined job/URL and all other providers are unchanged until activation.
- **16 daily + 5 weekly** registry series remain fetched **hourly**, protecting Rates & Policy, BTC Net Liquidity, Gold/USD evidence, weekly claims and daily cross-asset indices. **11 monthly + 1 quarterly** are fetched on official *publisher release dates* and the preceding two New York calendar days for bounded rechecks, plus one **full 33-series sweep daily at 04:31 UTC**. This 04 UTC sweep is an *operational safety choice*, NOT a guessed publisher time.
- One authenticated server-to-FRED \`fred/releases/dates\` calendar request, scoped by real-time dates, validates count and rows; on upstream error, malformed/partial/oversized calendar, missing provider key or unqualified registry, **fail open** to all 33 rather than skip ingestion. The planner uses \`America/New_York\` for source dates across DST; no hardcoded EST/EDT→UTC offset.
- The FRED monthly release IDs are taken from the **authenticated 33/33 production metadata qualification** recorded in [#229](https://github.com/LDonthepath/P365/issues/229#issuecomment-6054112556). Dates are from **FRED's source publisher calendar** and **do not prove first FRED availability**; daily full sweeps, two-day inclusive release windows, and all failure fallback protect against late availability.
- Safe operational reporting: provider response gains \`fredSchedule: {mode,calendarDateNY,requestedSeriesCount,releaseWindowSeriesCount}\`; no provider key, release timestamps, values or internal \`insertedCanonicalIds\` leak. Existing canonical/append-only writes, physical receipt, revision \`NOT_EVALUATED\` and backward-compatible BACKFILL unchanged.
- Activation [SQL](../scripts/ops/frs003_activate.sql) (DO NOT RUN without owner authorization): atomic \`cron.alter_job\` rewrites **existing jobid 4** to hourly **coingecko-context**, and \`cron.schedule\` adds hourly FRED-only release-aware job; both reuse the **existing Vault-based authenticated net.http_get command** without hardcoded credentials. Preconditions check exact schedule, unique URL parameter, no existing new job, expected deployment host and Vault reference. Rollback [SQL](../scripts/ops/frs003_rollback.sql) atomically restores original combined hourly FRED+context job and removes selective job.
